# Local Observation

Observation turns a synchronized directory into a validated [Snapshot](data-model.md). It is used before reconciliation, again during sync stabilization, and after execution. A full scan walks directories, records root and directory rows (including empty directories), hashes regular-file plaintext with BLAKE3, and finalizes parent Merkle hashes and sizes. File metadata and fingerprints are read around hashing; if a file changes while read, the scanner retries within a bounded window and then fails. Path and case-key validation fail closed. Symlinks are skipped; Windows private-path and reparse checks also guard state and mutation paths. See [Synchronized Path Rules](../configuration-and-usage.md#synchronized-path-rules).

## Ignore Projection

The root `.kasumiignore` supplies ordered, last-match rules. The scanner skips ignored entries before admitting them into the portable path namespace. When the ignore file differs between the accepted base, local disk, and remote effective tree, observation chooses effective rules before reconciliation: a local edit wins (including simultaneous edits); otherwise a changed remote `.kasumiignore` is fetched, decrypted, and verified against its committed hash and size, or a remote deletion selects empty rules. If selected rules differ from local rules, the local tree is rescanned as a managed projection. A missing or invalid remote ignore payload stops observation. This makes the ignore file itself part of synchronized state without applying stale rules to the wrong tree.

## Metadata Scans and Hash Reuse

Windows and Linux use the same scanner on every observation. Sync carries a `LocalObservationSession` containing only the SQLite path, loaded cache, and cache-loaded/cache-dirty flags. The scanner walks the current tree and reads native metadata; the cache avoids content reads, never the tree walk. A file hash is reusable only when logical path, entry kind, size, nanosecond modification time, and all native identity components match the cache contract. Windows uses volume serial and the full file ID; Linux uses device and inode. Missing identity forces full hashing and produces no reusable cache row.

Cache misses and explicit `FullHash` scans compute BLAKE3 and compare metadata before and after the read. Bounded retries and filesystem errors retain their existing behavior. Preview and Status scan with `FullHash`, as does an authenticated ignore projection that differs from local rules. Sync validates destructive Download, DeleteLocal, and RenameLocal targets with directed content hashing independently of cache reuse; mismatches invalidate the cached entry and trigger safe reconciliation. See [Synchronization](synchronization.md).

The session loads the persistent cache once when needed and replaces it only after a successful scan. An unchanged cache does not require persistence; changes and prior destructive invalidations remain dirty until finalization. Existing SQLite schema-v1 observation tables are ignored and left intact. New databases contain only the canonical state, pending materializations, metadata, and uniform file cache; no schema version or cache encoding change is needed.

Local scan and remote history loading can run concurrently. Sync [reobserves](synchronization.md) local and remote inputs after planning; later it scans again to validate the publication tree. Concurrent new paths outside the candidate tree are left on disk for another run, while changes to expected materialized rows cause a composition failure and rollback. These checks reduce races but do not create a filesystem snapshot or an exclusive lock on user files.
