# Preview and Status

`kasumi sync <profile> --dry-run` dispatches `application::Operation::Preview`; `kasumi status <profile>` dispatches `Operation::Status`. They are distinct CLI intents and response operation labels, but the application uses the same `run_plan` path and returns a `PlanReport`. `--full` changes CLI display truncation only. Neither command is a shortened Sync execution.

## Lifecycle

1. The CLI parses the operation and profile, then `application::execute` resolves the profile in read-only runtime mode, validates retention, acquires the **local** exclusive profile lock, resolves the persisted or supplied matching master key, and opens the configured transport. See [Application and Runtime](application-and-runtime.md).
2. The planner **does not call normal transaction recovery**. It loads the accepted `StoredState` reconciliation base from SQLite and reads `.kasumiignore`; a full-hash local scan and authenticated remote history observation run concurrently. Reconciliation can also download/authenticate a remote `.kasumiignore` to choose the effective projection. The remote observation can use the accepted Commit/Ciphertext ID and Epoch as frontier hints. Unlike Sync's `LocalObservationSession`, this path uses explicit full hashing and does not load or commit the file-hash cache. See [Local Observation](local-observation.md) and [History and Concurrency](history-and-concurrency.md).
3. [Reconciliation](reconciliation.md) validates local/base/remote continuity and derives a candidate shared tree and ordered `SyncPlan`. The planner converts operations to action/path rows and counts, upload/download byte totals, conflict flag, target generation, and pending-materialization paths. It reports a plan; it does not stage, transfer, apply, stabilize, or publish it.
4. The transport closes, key/credential buffers are wiped at cleanup points, and the profile lock is released. No accepted `StoredState` commit, transaction journal, content upload, Commit, HEAD marker, or Epoch publication occurs.

The synchronized tree is not intentionally mutated. Read-only resolution and private-path protection may still normalize local permissions; acquiring the lock can create/update its local lock file. The command reads `config.toml`, `key.bin` or an explicit key, SQLite state, the local tree, and remote history/content presence. A pending Sync transaction remains pending. It may affect what the plan can observe or make a later Sync recover first.

Invalid profile/key/transport, an inaccessible or invalid local tree, malformed accepted state, missing remote history for a persisted base, authentication/continuity failure, or reconciliation error is returned at preparation, observing, or calculating stage rather than repaired by the planner. The report is a **point-in-time observation**, not a reservation: local or remote state can change before a later Sync, which reobserves and may choose a different plan. `status` is a direct status query; `sync --dry-run` previews the actions that a Sync would currently plan. They share computation, not a guarantee of identical future effects. See [Synchronization](synchronization.md) for the executing path.
